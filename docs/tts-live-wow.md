# Задержка Barrens Voice в открытом WoW

WoW Forever работал в неподвижной сцене при разрешении клиентской области 3840 × 2560 на RTX 3060 12 ГиБ. Приоритет компаньона и настройки игры оставались штатными. В качестве воспроизводимого события использовалась кнопка «Проверка» в окне аддона. Обработчик кнопки ставит четыре локальные строки в очередь полоски. Для измерения выбиралась первая строка Громмаша «Всем привет! Кто идёт в Мёртвые копи?». Голос во всех прогонах один, `orc-male/standard`. Отправка сообщения другим игрокам для такого теста не требуется.

Время отсчитывается от отпускания кнопки мыши до первого ненулевого звукового блока с уровнем выше 0,001 полной шкалы по часам PortAudio. Между ними записаны системное время первого кадра Windows Graphics Capture, в котором удалось найти строку на полоске, и время передачи декодированной строки в обработчик компаньона. Эти часы приведены к Windows QPC. Окно активного клиента контролировалось каждые 100 мс. Аудиовыход использовал реальный драйвер с приглушением после измерения. Сетевая доставка от другого игрока, акустическая задержка и субъективная оценка на слух сюда не входят.

В полном тракте работал один штатный захват WGC с интервалом обновления 40 мс и опросом через 50 мс. Синтез и проигрыватель запускались в отдельном процессе для каждого профиля. Сохранённый движок TensorRT загружался с диска. Первая реплика каждого профиля подавалась после штатного прогрева графов. В испытании синтезировалась только первая строка каждого нажатия. Это позволяет сравнить одинаковое сообщение при пустой очереди.

## От нажатия до речи

Столбцы с несколькими числами показывают последовательные нажатия. Во время всех завершённых измерений на переднем плане был WoW.

| Профиль | Подготовка и прогрев, с | До первого кадра полоски, мс | До обработки строки, мс | До звука, мс |
| --- | ---: | --- | --- | --- |
| quality | 89,0 | нет замера | нет замера | синтез превысил лимит 90 с |
| fastest CUDA | 62,5 | 230 / 80 / 63 | 292 / 107 / 96 | 35688 / 1854 / 1860 |
| fastest TensorRT | 36,0 | 130 / 80 / 64 | 276 / 83 / 90 | 8784 / 690 / 690 |

На первом нажатии у TensorRT вызовы Transformer по всей строке заняли 7,94 с. На двух повторах они заняли 0,76 с каждый. Таймаут означает, что стенд прекратил ждать завершения синтеза. Такое наблюдение исключено из расчёта медиан.

## Время кадров

Кадры записывались через установленный NVIDIA FrameView SDK из отдельного процесса. Из потока выбраны события `Present` процесса WoW для основной цепочки вывода. Повторы одной записи исключены по идентификатору цепочки и QPC. В статистику синтеза входят только полные межкадровые интервалы, лежащие между передачей строки обработчику и готовностью последнего аудиопакета. Для фона без синтеза взяты интервалы от 2 до 0,2 секунды перед повторными нажатиями в той же сцене с открытым окном аддона. Средний FPS равен числу кадров, делённому на сумму этих интервалов.

| Интервал | Кадров | Средний FPS | Кадр p95 / p99, мс | Максимум, мс | Дольше 33,3 мс |
| --- | ---: | ---: | ---: | ---: | ---: |
| Перед повторными нажатиями | 559 | 78,2 | 14,6 / 15,8 | 18,6 | 0 |
| fastest CUDA, первое нажатие | 2877 | 77,8 | 14,4 / 26,3 | 32,6 | 0 |
| fastest CUDA, повторные нажатия | 264 | 40,7 | 27,3 / 28,4 | 28,8 | 0 |
| fastest TensorRT, первое нажатие | 686 | 77,1 | 14,9 / 26,4 | 28,2 | 0 |
| fastest TensorRT, повторные нажатия | 72 | 40,4 | 29,1 / 30,2 | 30,4 | 0 |

Даже при быстром начале речи рендеринг замедлялся. На двух повторных репликах с TensorRT средняя частота составляла около 40 кадров/с. Этот интервал длился примерно 0,9 с на реплику.

## Прогоны без нажатия кнопки

При активном окне WoW отдельный прогон `fastest` с TensorRT пропустил три короткие и три длинные фразы фиксированного корпуса через обработчик компаньона. Время до звука после передачи строки составило 8095, 592 и 667 мс для коротких, 641, 643 и 705 мс для длинных. Во время генерации зарегистрировано 788 полных межкадровых интервалов, средняя частота 66,0 кадра/с, p95 27,4 мс и максимум 30,4 мс.

При смене активного окна клиент ограничил частоту до 30 кадров/с. В таком режиме медианы на тех же трёх коротких и трёх длинных репликах составили 2695 / 6756 мс у `quality`, 1465 / 1519 мс у `fastest` CUDA и 533 / 515 мс у `fastest` TensorRT. К моменту первой холодной реплики TensorRT происходил переход в фон. Все шесть реплик его прогретого корпуса пришлись на 30 кадров/с. Результаты фонового клиента учитываются отдельно.

В первом диагностическом прогоне при активном WoW были открыты два независимых захвата WGC. При полной загрузке GPU подготовка `quality` заняла около 95 с, а обработка первого сообщения превысила 90 с. Для измерений по кнопке использовался один захват. По этим наблюдениям нельзя разделить влияние нагрузки игры, планировщика GPU и дополнительных захватов.

Числа описывают одну сцену, одну карту, текущее разрешение и выбранную нагрузку. Три нажатия позволяют увидеть первый и повторные отклики, но недостаточны для устойчивой оценки p95 задержки озвучки. В рейде, бою или насыщенном чате очереди и частота кадров могут быть другими.

В [архиве измерений](benchmarks/wow-rtx3060.zip) лежат числовые отметки кнопки, полоски, обработки и звука, трассы синтеза, интервалы кадров по окнам сравнения и отдельно сведения о таймаутах.
