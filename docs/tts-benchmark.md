# Задержка озвучивания на RTX 3060

Таблица ниже относится к версии с выводом через MME. Замеры новой версии с предварительным открытием WASAPI и кэшем фраз на том же наборе из 60 сообщений приведены в отчёте по активному игровому клиенту. В активной сцене нагрузка игры существенно повлияла на время первого отклика и время кадра. [Проверка в WoW Forever](tts-live-wow.md)

## Измеренная задержка

Измеряемый интервал начинается при передаче декодированной строки чата компаньону и заканчивается на оценке времени первого слышимого отсчёта в PortAudio. Каждая строка таблицы получена отдельным процессом на одном наборе из 30 коротких и 30 длинных реплик. p50 и p95 посчитаны отдельно для каждой длины с линейной интерполяцией. RTF учитывает всю строку, включая продолжение после первого звука. Холодная реплика исключена из перцентилей.

| Профиль | Короткие, p50 / p95, мс | Длинные, p50 / p95, мс | RTF p50, короткие / длинные | VRAM процесса, максимум замеров, МиБ | Пик RAM, МиБ |
| --- | ---: | ---: | ---: | ---: | ---: |
| Исходный `7d0c8fa` | 1615 / 2935 | 3391 / 7089 | 1,05 / 0,43 | 2453 | 3599 |
| `quality`, CUDA | 1633 / 2900 | 3373 / 6939 | 1,05 / 0,43 | 2453 | 3601 |
| `balanced`, CUDA | 1226 / 2156 | 2469 / 4974 | 0,72 / 0,30 | 2595 | 4373 |
| `fastest`, CUDA | 826 / 923 | 928 / 1611 | 0,49 / 0,25 | 2593 | 4373 |
| `fastest`, TensorRT 10.16.1.11 | 361 / 505 | 394 / 602 | 0,14 / 0,06 | 1777 | 9389 |

На этом стенде `fastest` с обычным CUDA сократил p50 в 1,96 и 3,65 раза. С TensorRT выигрыш относительно исходной версии составил 4,47 и 8,61 раза. У `quality` короткий p50 вырос на 17 мс (+1,1 %), длинный уменьшился на 18 мс. Для оценки разброса между запусками потребуется несколько независимых прогонов каждого профиля.

## Что занимало время

До изменений сумма вызовов Transformer на сообщение имела p50 **1233 мс** на коротких строках и **2832 мс** на длинных. Медиана Decode составляла 29 и 107 мс, RUAccent занимал 2,5 и 27,7 мс. Отметки каждого шага Transformer сохранены в JSONL. При пустой очереди ожидание синтезатора и проигрывателя составляло около 0,03 и 0,10 мс соответственно. Помимо десяти проходов Transformer сказывались повторные синтезы и ожидание готовности всей строки.

| Этап, p50 в мс | Исходный, короткие / длинные | `fastest` CUDA, короткие / длинные |
| --- | ---: | ---: |
| Обработка текста в обработчике чата | 0,17 / 0,37 | 0,16 / 0,37 |
| RUAccent | 2,50 / 27,72 | 2,56 / 26,05 |
| Preprocess, сумма по строке | 5,28 / 10,67 | 8,43 / 18,42 |
| Один вызов Transformer | 121,51 / 238,46 | 101,42 / 149,83 |
| Все вызовы Transformer в строке | 1233 / 2832 | 608 / 1701 |
| Decode, сумма по строке | 28,53 / 106,82 | 7,23 / 15,49 |
| Приём строки до первого callback со звуком | 1393 / 3146 | 724 / 816 |

Для `fastest` с TensorRT один вызов Transformer занял в медиане 24,6 мс на коротких и 31,7 мс на длинных фразах.

Ускоренные профили используют FP16 уже поставляемого Transformer, корректное расписание Эйлера, буферы OrtValue, передачу промежуточных тензоров между тремя графами на GPU и CUDA Decode. При прогреве компаньон сверяет CUDA Decode с CPU на одном и том же входе. В отдельной трассе ORT у Preprocess 131 узел на CUDA, у Transformer 850. В Decode 113 узлов на CUDA и три на CPU (`Gather`, `Unsqueeze`, `Concat` ветви iSTFT). В `fastest` синтез второго пакета перекрывается с проигрыванием первого. На длинной фразе без подходящей границы полного первого пакета всё равно нужно дождаться. Исходный кэш текстов и PCM голосовых образцов и прогрев графов сохранены. Настройка темпа речи и алгоритм расчёта длительности одинаковы. Медианы длительности готовых WAV без заключительной защитной паузы составили 1,38 / 7,25 с у базы и 1,35 / 7,02 с у `fastest` CUDA. Сокращение времени до первого отсчёта измерялось отдельно от длительности реплики.

## Холодный процесс

Модели уже скачаны, голосовой банк построен. Измерение охватывает импорт библиотек, загрузку моделей, подготовку производного графа при отсутствии в кэше и штатный прогрев. После готовности движка первой поступает отдельная реплика «Проверка связи.». Это один холодный запуск на конфигурацию.

| Профиль | До готовности, с | От старта до первого звука, с |
| --- | ---: | ---: |
| Исходный | 16,70 | 19,93 |
| `quality` | 14,82 | 17,92 |
| `balanced`, пустой кэш экспортов | 15,47 | 17,75 |
| `fastest` CUDA, пустой кэш экспортов | 16,75 | 17,73 |
| `fastest` TensorRT, первая сборка движка, производный ONNX уже на диске | 63,81 | 64,24 |
| `fastest` TensorRT, сохранённый движок | 17,21 | 17,65 |

Перед измерениями рабочий стол и другие процессы уже занимали около 3,8 ГиБ VRAM. Максимум по всей карте между сообщениями достиг 6389 МиБ в исходном прогоне, 6434 МиБ в `fastest` CUDA и 5618 МиБ в `fastest` TensorRT.

В дополнительном прогоне с пустым кэшем опрос Windows Dedicated Usage каждые 100 мс показал максимум 1441 МиБ у CUDA и 1629 МиБ у TensorRT за время запуска. За последующие две пары сообщений максимумы с начала процесса достигли 2465 и 1649 МиБ соответственно. Счётчик относится к выделенной памяти конкретного процесса и может пропускать кратковременные пики.

Сборка TensorRT потребовала пикового рабочего набора 9,17 ГиБ. При повторном запуске с кэшем пик за тест на одной паре был 6,00 ГиБ. Компилированный движок занял ещё 633 МиБ на диске помимо 630 МиБ производного ONNX и 2,17 ГиБ установленных DLL.

## Качество

- Для всех 60 WAV `quality` сохранилась исходная длительность. У 40 записей идентичны все PCM-отсчёты, у остальных максимальная разница составила одну единицу PCM16. Для исходной версии и `quality` среднее сходство слов по Whisper составило 0,996, эвристика проекта обнаружила окончание у 60 из 60.
- У `fastest` CUDA результат составил 0,996 и 60/60, у `balanced` 0,975 и 60/60. У `balanced` были отдельные ошибки распознавания, включая «подчиниться» вместо «починиться». Проверка окончания использует допуск проекта и может пропустить замену похожего слова. Это оценка распознавателем.
- Для `fastest` с TensorRT среднее сходство составило 0,993, окончания обнаружены у 60/60, минимальный RMS 0,0716, пик 0,906, максимальный скачок на границе цифровой паузы 0,0083, опустошений буфера 0. Медианный подъём F0 шести вопросов составил 5,83 полутона, у одного вопроса всего 0,7 полутона.
- На сетке из четырёх шагов среднее сходство было 0,387 и 33/60 окончаний. Изменённые границы первых шагов дали 0,900 на 12 фразах, но одна короткая реплика получила сходство 0. Пять шагов дали 0,927 и 58/60 на полном корпусе. Для `fastest` выбраны шесть. Все испытанные расписания доходят до конечного времени диффузии.
- В выходе `fastest` CUDA минимальный RMS составил 0,0716, максимальный пик 0,838 полной шкалы. Максимальный скачок на границе цифровой паузы длиной от 20 мс составил 0,0109 против 0,0085 у базы. Для шести коротких да/нет-вопросов медианный подъём F0 в конце составил 6,31 полутона против 6,48 исходно. В журнале синтеза сохранилась разметка RUAccent, в том числе «гот+овы» и «порт+ала». Слуховая оценка носителем языка и проверка на других голосах остаются открытыми.
- В полном прогоне `fastest` CUDA зарегистрировано ноль сообщений PortAudio об опустошении буфера. В отдельном прогоне через полные пакеты на трёх парах также было ноль. Интервалы между слышимыми частями длинных реплик составили 333–512 мс, включая естественную паузу и повторное открытие потока устройством MME.
- После запроса `fastest` на DirectML нативный тест получил исходные 10 шагов и звуковой сигнал. При принудительном отсутствии GPU-движка штатный путь через Windows SAPI дал 3,08 с звука с пиком 0,674.

## Конкуренция за GPU

Отдельный процесс обычного приоритета ставил на GPU шесть последовательных MatMul 1536 × 1536 до 60 раз в секунду. Синтез шёл в другом процессе со штатным пониженным приоритетом CPU и GPU. Для каждого режима измерялись 10 с без компаньона и затем четыре пары реплик после прогрева. Нагрузка использовала либо CUDA, либо очередь Direct3D 12 через DirectML. Длительность кадра включает ожидание завершения операции на CPU. В фоне работал бенчмарк с обычным сбором метрик.

| Очередь нагрузки | Синтез | p95 без синтеза, мс | p95 / p99 с синтезом, мс | Максимум, мс | Дольше 33,3 мс / всего |
| --- | --- | ---: | ---: | ---: | ---: |
| CUDA | quality | 6,8 | 95,7 / 126,4 | 155,5 | 331 / 1025 |
| CUDA | fastest CUDA | 6,8 | 63,0 / 91,4 | 103,6 | 174 / 784 |
| CUDA | fastest TensorRT | 6,7 | 6,2 / 103,5 | 125,4 | 26 / 761 |
| Direct3D 12 | quality | 6,8 | 139,6 / 190,5 | 202,6 | 235 / 890 |
| Direct3D 12 | fastest CUDA | 6,9 | 83,1 / 129,2 | 146,7 | 142 / 705 |
| Direct3D 12 | fastest TensorRT | 6,9 | 6,9 / 119,0 | 211,6 | 21 / 756 |

В Direct3D-проверке с TensorRT p95 остался около 7 мс, но 21 кадр из 756 занял дольше 33,3 мс. Редкие задержки сохраняются. Клиент WoW с вошедшим персонажем в этой серии не работал. Последующая проверка кнопкой аддона в игровом мире дала отдельные [цифры задержки и времени кадров WoW](tts-live-wow.md).

Для повторения используйте `tools/tts_frames.py` с теми же аргументами банка и профиля, что у `tts_bench.py`, и с `--pairs 4`. Для Direct3D установите `onnx` и ONNX Runtime DirectML в отдельное окружение для нагрузки и передайте `--renderer dml --synth-python C:\путь\к\cuda-venv\Scripts\python.exe`. CUDA-компаньон запускается как дочерний процесс.

## Проверка совместимости и тесты

На чистом Windows-раннере прошли 489 тестов Python, пять наборов Lua и упаковка аддона. Тесты профилей проверяют конечную точку расписаний, неизвестный экспорт, сбой CUDA Decode при загрузке, переход TensorRT → CUDA и CUDA → исходный F5 на той же строке, отмену второго пакета и возврат к обычному размеру буфера. [Прогон Windows CI](https://github.com/sokol-rc/barrens-voice/actions/runs/45051419099)

Исходный коммит отдельно проверялся на машине с установленным WoW и в WSL. В нативной исходной версии 11 локальных сбоев связаны с обнаружением реальной установки игры и геометрией окон Tk. В WSL было шесть сбоев проверок переноса строк и геометрии и один пропуск. Чистый Windows CI изолирует эти зависимости окружения.

## Условия

Windows, GeForce RTX 3060, 12 ГиБ VRAM, драйвер 610.88, ONNX Runtime GPU 1.32.0, Python 3.13.18. Исходный компаньон взят из коммита `7d0c8fa`. Все профили работали с одними моделями из ревизии Hugging Face `00ae48f1aff7f2f5ba1a64e425bb5c944f0d70d9` и с одним банком WoW Forever. В каждом прогоне чередовались голоса `orc-male/standard`, `human-female/official` и `dwarf-male/standard`. Громкость, темп, словарь, RUAccent, параметры интонации и приоритеты компаньона обычные. Данные бенчмарка и назначения персонажей записывались отдельно от установки игрока.

Один процесс обслуживает 30 пар русских фраз из [фиксированного корпуса](../tools/tts-corpus.txt). Он прогревает F5 штатной репликой, проводит отдельный замер первого сообщения и затем обрабатывает 60 строк без начальной очереди. Генератор ONNX Runtime получает seed 42. Входное событие попадает в `Lines.handle`, проходит словарь, склонение, очередь F5, синтез, обработку интонации и очередь общего проигрывателя.

Начало речи определяется по первому отсчёту выше 0,001 полной шкалы в callback реального выходного устройства. Используются часы PortAudio. К моменту callback прибавляются разница между `outputBufferDacTime` и `currentTime` и смещение отсчёта в блоке. Это оценка времени подачи сигнала устройству. Измерение начинается после разбора кадра компаньоном. Время ожидания полоски, захват экрана, задержка беспроводных наушников и акустическое распространение в эти цифры не входят.

Для основной серии устройство получает начало пакета, достаточное для измерения первого звука. Чтобы не проигрывать сотни реплик вслух, стенд заполняет блок нулями после фиксации времени. Полный PCM до приглушения сохраняется для Whisper и проверки стыков. Параметр `--full-playback` проигрывает через тот же callback все блоки каждого пакета с тем же приглушением. Синтез всегда доходит до конца сообщения. RTF здесь равен времени от приёма строки до готовности последнего пакета, делённому на длительность звука без заключительной защитной тишины проигрывателя.

## Как повторить

В PowerShell из каталога ветки, на Windows с NVIDIA и готовым банком, выполните команды ниже. Подставьте каталог установки в первой строке. Для каждого профиля запускается отдельный процесс.

```powershell
$install = 'C:\Games\BarrensVoice'
$env:PYTHONUTF8 = '1'
uv sync --frozen --extra cuda
foreach ($profile in 'quality', 'balanced', 'fastest') {
    uv run --frozen --extra cuda python tools/tts_bench.py --bank "$install\data\voices\bank.json" --hf "$install\cache\hf" --profile $profile --wav-dir "wav-$profile" |
        Out-File -Encoding utf8NoBOM "$profile.jsonl"
}
uv run --frozen --extra cuda python tools/tts_score.py --hf "$install\cache\hf" wav-quality wav-balanced wav-fastest
uv run --frozen python tools/tts_summary.py quality.jsonl balanced.jsonl fastest.jsonl
```

Для PowerShell 5 используйте перенаправление stdout через `cmd.exe` с `PYTHONIOENCODING=utf-8` либо PowerShell 7 с `utf8NoBOM`. Для воспроизведения базы скопируйте только файлы `tools/tts_bench.py` и `tools/tts-corpus.txt` в отдельный checkout `7d0c8fa`. Запустите его тем же интерпретатором и теми же параметрами с `--profile quality`. Файлы установленного банка и моделей используются для чтения. При переносе банка на другой компьютер пути в нём должны указывать на существующие образцы.

В JSONL сохранены монотонные часы приёма и постановки в очередь, время каждого вызова RUAccent, Preprocess, каждого шага Transformer, Decode, обработки интонации и PCM. Поле `synth_queue_ms` измеряет ожидание синтезатора, `play_queue_ms` - ожидание первого пакета в проигрывателе. `callback_ms` и `dac_ms` отсчитываются от одного входного события. Числа в `process_vram_mib` берутся из счётчика Windows Dedicated Usage для PID после каждой строки. Пик коротких временных выделений внутри шага может быть выше. `gpu_used_mib` охватывает всю карту, включая рабочий стол. `rss_peak_mib` - максимальный рабочий набор процесса с запуска.

Для повтора с TensorRT передайте `tts_bench.py` параметры `--profile fastest --trt-dir C:\путь\к\tensorrt_libs --graph-cache C:\путь\к\кэшу`. Пустой каталог позволяет измерить компиляцию при первом запуске. Повторите команду с тем же каталогом для замера загрузки готового движка. Опция `--sample-vram` включает отдельный опрос памяти процесса с шагом 100 мс, начиная до загрузки F5. [Установка библиотек TensorRT](config.md#голоса-рас-f5)

Исходные JSONL, оценки Whisper, размещение операторов ORT и отдельные прогоны проверки собраны в [архиве результатов](benchmarks/rtx3060.zip). После распаковки выполните команду из каталога репозитория.

```powershell
uv run --frozen python tools/tts_summary.py results/before.jsonl results/quality.jsonl results/balanced.jsonl results/fastest.jsonl results/tensorrt.jsonl
```

Основное сравнение использует пять файлов в корне `results`. В `experiments` находятся дополнительные прогоны с отдельными настройками и поднаборами. Самые ранние замеры начинаются на этапе подготовки реплики и хранят меньше полей. В основной таблице используются только сопоставимые записи от входа в `Lines.handle`. В `checks` лежат результаты проверки длинных потоков, размещения узлов, запасных движков, памяти и конкуренции за GPU.
